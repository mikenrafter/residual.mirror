## Architecture rules
1. **CLI** is thin hub. Process/fluency text lives **beside each clap action**, not a shared preamble. Whole-system-residue reminder is text next to add force/residue.
2. **cli-help** owns completions / man / generate help.
3. **skills-phases** owns list + show + data + ATAM/FMEA skill content.
4. **skills-personas** and **skills-research** stay SPLIT. Do NOT fuse. research-study is NOT a runtime module.
5. **verification** pulls policy from **storage-config** (super-strict, token_warn, etc.). No `verification/config.rs`.
6. Lexicon continuity: ≥1 terminology word in each force **outcome** AND ≥1 in each force **shortname**.
7. Tag rule: metadata-only OK; tagged-in-code ⇒ must exist in metadata. Tag scan suggests; verification enforces one-way.
8. Personas: verification requires min:2 personas until α/β exist.
9. **structure** is the only external grouping API. Analysis and Definition types know grouping internally; callers use `structure`.
10. Analysis = NKP + tag-scan + force/residue schemas. ATAM/FMEA only in skills-phases.
11. Storage supports read / write / **mutate** (not append-only).
12. Migration: naive → v3 only. Alternate backends deferred.
