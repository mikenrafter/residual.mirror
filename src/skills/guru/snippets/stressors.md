**Stressors** — forces that push the system from the positive attractor state toward the negative. Judge stressors by narrative coherence, never by likelihood or impact score — residuality is probability-free. Archaeological source: `git log --stat --oneline | head -40` surfaces wide-spanning commits (coupling the architecture was naive to) and recurring churn (rework the design did not anticipate).

**Stressors are not bugs.** A bug is a defect in already-decided behavior — something concrete is broken relative to a spec or contract that already exists, and the fix is to restore that contract. A stressor is a narrative about how the wider world could move the system to a different attractor — there is no existing decision to be "wrong" about yet, only a coherent story of pressure. The two can overlap (a bug report can be the first evidence that a stressor already materialized), but recording every bug ticket as a stressor, or treating a stressor as merely a bug waiting to be triaged, erases a distinction the ledger depends on. If the fix is "restore the behavior we already promised," write a bug ticket, not a stressor.
